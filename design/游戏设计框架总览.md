## 1. 游戏定位与技术架构

| 项 | 内容 |
|---|---|
| 类型 | 纯前端**回合制修仙放置**网页游戏（单机、离线可玩） |
| 线上地址 | https://jamesth258.github.io/--game/ （GitHub Pages，`master` 分支） |
| 技术栈 | 原生 HTML5 + Canvas + JS，**零框架零构建**；`index.html` 骨架 + `css/style.css` + 根目录脚本 + `js/*.js` 模块 |
| 存档 | 浏览器 `localStorage`，键 `wuxia_save`；**无服务器、无账号、无上传** |
| 联网 | 腾讯云 CloudBase（`online.js` + `config.js`），当前 `config.js` 为空 → **离线降级**（排行榜等占位） |
| 部署 | `deploy_api.py`（GitHub Git Data API 直推，绕过沙箱 git 传输重置）；Pages 约 1–2 分钟重建 |

**加载顺序铁律**：`assets/vendor/tcb.js → config.js → cultivation.js → js/core.js → js/player.js → js/battle.js → js/hub.js → js/create.js → js/daily.js → js/worldboss.js → js/main.js → online.js`。跨文件共享变量靠「同全局词法作用域 + 加载顺序」；**被 HTML `onclick` 调用的函数必须挂 `window`**（见 §6 坑点）。

## 2. 核心系统清单（13 个）

### 2.1 角色与境界（`cultivation.js` + `player.js`）
- **26 大境界 / 168 小阶**（炼气→…→宇宙国主），经验曲线 `req(i)=200+20i+24i²`，满级总修为≈3724 万。
- 设计目标：≥1 年满级（挂机 2/秒、离线 1/秒、封顶 12h/天）。
- `CULTIVATION.realmFromXp(xp)` 返回 `label/progress/globalIndex(0~167)/isMax`，派生属性与加点全用 `globalIndex`。
- **唯一数据源**：`syncRealmDOM()`（`hub.js`）写 4 个 DOM，新增改 xp 的逻辑必须调它。

### 2.2 属性与加点（`player.js`）
- 6 基础：`con`体质/`str`力量/`sou`灵魂/`spd`速度/`com`悟性/`des`天命（开局各 10）。
- 派生：`maxHp/def/atk/maxMp/spiAtk/spiDef/init/eva/hitRate/critRate/critDmg/luck/xpBonus`（由 `recalcStats` 聚合 6 基础 + 境界 + 装备 + 被动功法 + 套装）。
- 加点：每突破一小阶 +10 点，属性下限 10。

### 2.3 装备系统（`equip_db.js` + `player.js`）
- **94 种基础装备 + 6 套装 + 16 特效**，4 部位（武器/护甲/法宝/战靴），5 品质（凡/灵/宝/仙/神）。
- 主特效 `effect` + **副特效 `effect2`**（8/20 新增：12 件补暴伤≤20%、12 件补暴击率≤20%，均走「补旧装」而非新增装备）。
- **动态回填铁律**：`resolvedEquipEffects(item)` 实时查 `EQUIP_DB_MAP` 回填旧存档装备；单件命中≤40%、单件闪避≤50% 封顶。
- 套装：`EQUIP_SETS` 在 `recalcStats` 聚合。

### 2.4 功法系统（`skills-data.js` + `battle.js` + `hub.js`）
- **130 种功法，68 被动 / 62 主动**（8/21 重设计，零重复）。
- **被动**（`kind:"passive"`）：9 种属性各 7–8 个递进数值（pasAtk/pasSpiAtk/pasDef/pasInit/pasHp/pasMp/pasHit/pasCrit/pasCritDmg），自动加成。
- **主动 11 类效果**：`dmg`(含 pierce 穿透/lifesteal 吸血)/`debuff`(四维)/`buff`(四维+暴击)/`heal_hp`(每品阶1个，15%→50%)/`heal_mp`(每品阶1个，12%→50%)/`stun`/`poison`(新)/`shield`/`absorb`/`critup`；**10 个带 `buffHitRate:0.2`**（临时+20%命中）。
- 战斗守卫：`buildSkillBar` 过滤被动；功法库分主动/被动两栏 + 品阶筛选/排序。
- **铁律**：任何两功法效果不得完全相同；每品阶配齐回血+回蓝且高阶比例大（帝阶均 50%）。

### 2.5 战斗系统（`battle.js`）
- 回合制：`beginRound→processTurn→playerAct/enemyAct→checkEnd`，先攻多段（速度比≥2× 得连动 `floor(ratio/2)+1` 次）。
- 双伤害轴：物理(受 `def`)/精神(受 `spiDef`)，**扣同一条血**。
- 结算：`damage()` 含暴击(`0.15+level*0.2%+…+buff`≤1.0)、暴伤(`1.5+mods.critDmg`)、命中(`min(1,hitRate)-eva`，负值 floor 12.5%)、闪避、护盾、吸血、反伤。
- 状态机：`buff/debuff/stun(跳过)/poison(每回合 tick)/shield/absorb/critup` 在 `beginRound`/`applySkill` 消费。
- **飘字**：`floats` 数组 + `drawBattle()` 渲染，坐标 `_x/_y` 锁在对象创建时（8/21 修 pierce 14 技能漏推 + 坐标 NaN 两坑）。

### 2.6 副本剧情（`story-data.js` + `story.js`）
- **100 章**线性解锁，首通奖励 `+(10+章节序号)` 灵石；三选一奖励（`showStoryReward`）。
- `storyLevelFirstClear` 首通判断；重战不重复发首通（`taskClaimed` 守卫）。

### 2.7 每日任务与签到（`daily.js`）
- **三重载**：①每日签到（灵石=境界等级×100；月签到 7/14 天发 1000/2000 钻）；②在线时长（5/15/30/60 分钟发 10/20/宝箱/混合钻）；③日常任务里程碑（副本10关/BOSS 5·10·15·20 次）。
- `ensureDaily()` 跨天/跨月重置**当日**与**当月**状态（8/22 补 `shopRefreshCount` 跨天归零）。

### 2.8 世界BOSS（`worldboss.js`）
- **5 时段/天**，排名系统 `wbBoard`（**当前为本地 NPC 种子对手**，未接 CloudBase）。
- 参与奖（rank4+）：每时段 2 灵石宝箱 + 5 经验宝箱（8/21 压 5→2 灵石宝箱）。
- 功法/装备宝箱：`openSkillChest`(120 保底)/`openEquipChest`。

### 2.9 图鉴（`codex.js`）
- 装备收集进度，每完成 10 个发 **1000 钻**（一次性，全完成 +1000 钻）。

### 2.10 宝箱抽奖（`worldboss.js` + `hub.js`）
- 功法按阶权重 `SKILL_TIER_WEIGHTS=[0,38,26,16,10,5,3,2]`，**保底 `SKILL_PITY_LIMIT=120`**（满 120 强制帝阶）。
- 装备宝箱：`rollRarity()` + 来源 bias。
- 宝箱为道具入背包，手动开启（带开启动画）。

### 2.11 商店（`hub.js`）
- **钻石专区**（钻石消费）：功法宝箱/装备宝箱 200 钻、灵石宝箱/经验宝箱 50 钻。
- **灵石专区**（灵石消费）：4 部位各 1 件随机品质，右侧「🔄 刷新」按钮。**每日前 10 次免费刷新**；第 11~20 次为**灵石付费刷新**，每次消耗 **500 灵石**；共 20 次/天（跨天随 `ensureDaily` 归零 `shopRefreshCount`）。首次打开/跨天后内存清空时自动补一份库存（不计入刷新次数）。
- 价格表见 §3。

### 2.12 排行榜（`online.js` + `hub.js`）
- 接 CloudBase 真实榜；`config.js` 为空时 `hub.js` 弹「联网功能尚未开启」占位。**当前即占位态，无造假数据**。

### 2.13 挂机（`player.js` + `hub.js`）
- 在线 2/秒×(1+xpBonus)，离线 1/秒 封顶 12h（`applyOfflineXp`，8/22 修：结算后回写 `lastSeen`+落盘防重复领取）。
- 每 5 秒 `saveGame()` 落盘。

## 3. 经济系统（双货币）

### 3.1 灵石（日常货币）
| 来源 | 中等玩家/天（realm≈30） |
|---|---|
| 签到（境界×100） | 3,000 |
| 在线 60min（灵石宝箱×2） | 1,000 |
| 副本首通（~10 关，一次性） | ~150 |
| 日常·通关10关 | 500 |
| 日常·BOSS 5/10 次 | 1,000 |
| 日常·BOSS 15 次（灵石宝箱×5） | 2,500 |
| 世界BOSS 参与奖（5 时段×2 宝箱） | ~5,000 |
| **合计** | **~13,150** |

**商店价（购买 / 出售 = 25% 回收）**：凡 500/125 · 灵 2,000/500 · 宝 8,000/2,000 · 仙 50,000/12,500 · 神 200,000/50,000。
→ 中等玩家买**单件神品≈15 天**、**一套神品≈60+ 天**、仙品单件≈4 天。经济已收敛为「资源黑洞」。

### 3.2 钻石（稀有货币）
- **保底白嫖 210 钻/天**（在线 5/15/60min=10/20/30 + BOSS 10/15 次=50/100）；月签到摊薄≈100 钻/天（第 7/14 天集中发）；图鉴全完成一次性 +1000。
- 消耗：功法/装备宝箱 200、灵石/经验宝箱 50。
- 月获取上限约 3,060 钻 → 抽卡深度有限（设计有意：钻石为稀有资源）。

### 8/24 新修复（commit `0cc559bcca5d`）
- **B1 被动心法暴击率/暴伤未进入战斗判定**（用户实测：面板满暴击、实战经常不出暴击）。
  - **根因**：属性面板 `player.critRate`（`player.js` 的 `recalcStats`）计入被动心法 `pasCrit/pasCritDmg`，但战斗实弹 `damage()` 的 `critChance` 只取 `aMods.critRate`，而 `aMods` 来自 `computeEquipMods()`——它**只遍历装备特效 + 套装常驻项，漏算 `player.learned` 被动心法**。靠被动功法堆到面板 100% 时实战不含这部分，故不出暴击。
  - **修复**：`computeEquipMods()` 末尾累加 `player.learned` 被动 `pasCrit→m.critRate`、`pasCritDmg→m.critDmg`，使面板与实战同源（唯一真源）。
  - **回归**：`test/crit_panel.test.js` 新增 G) 断言（bu018 被动暴击进战斗=0.09、bu006 被动暴伤进战斗=0.30）全绿；全量 9 套测试除 `equip.test.js` 2 项历史欠账外全绿。

### 8/24 二次修复（commit `9a4cf3f46dfa`，用户复测仍「很少出暴击」后深挖）
- **B2 穿透功法暴击锁死 15%（真 bug，普通攻击 fix 后仍不暴击的主因之一）**。
  - **根因**：`applySkill` 的 pierce 支路（`battle.js`）硬编码 `const crit = Math.random() < 0.15`，**完全无视** `aMods.critRate`（装备+被动暴击）、`baseCrit`（等级/天命）、`aMods.critDmg`。用带穿透的功法打伤害时，暴击恒 15%，堆再多暴击也白费。无头模拟实测：带 bu018 被动暴击仍只有 ~15%（修复后达 ~34%，与面板同源）。
  - **修复**：pierce 支路改为复用与 `damage()` 一致的暴击公式（`baseCrit + aMods.critRate` + 积威/濒锋 + 暴伤 `critMul=1.5+aMods.critDmg`），飘字文本同步。
  - **回归**：`test/crit_panel.test.js` 新增 H) 确定性断言（固定 `Math.random` 证明穿透功法吃被动暴击），全绿。
- **B3 前期基础命中率过低（「打不出暴击」观感的核心）**。
  - **根因**：`recalcStats` 基础命中 `0.25 + idx*0.005 + com*0.002`，前期低阶号（globalIndex≈0）实测命中 ~27%，叠加敌方闪避 ~5% → **~78% 攻击直接「未命中」**，根本不进暴击判定，观感就是「很少出暴击/没伤害数字」。
  - **修复**：基础命中抬至 `0.80 + idx*0.004 + com*0.002`（前期 ~80–96%）；`battle.js` 命中兜底 `|| 0.25` → `|| 0.80`。无头模拟实测前期真实命中率从 ~22% 抬到 ~77%。
  - **连带**：`test/backfill.test.js` 的 A4/A5 原写死「增量 0.40/0.34」，因基础命中抬升后低阶角色基础 0.80+神装 0.40 封顶 100% 被压缩，改为守护「装备命中确实进面板（with>base）」，现 18/0。
  - **全量回归**：9 套测试全绿（含此前 `equip.test.js` 2 项历史欠账也已修，现 18/0）。

## 5. 设计合理性评估（回答：是否合理？是否初具模型？）

### 已具备的仙侠放置闭环 ✅
1. **养成主轴完整**：境界(168 阶) → 属性加点 → 装备(94+6套装+副特效) → 功法(130，被动自动/主动手动) → 战力，环环相扣。
2. **双货币经济分工清晰**：灵石=日常产出/消耗（商店主力），钻石=稀有/抽卡（签到+任务）。经多轮平衡已收敛（神品≈15 天收入，非「半天买齐」）。
3. **多获取渠道防单点依赖**：副本/每日/签到/BOSS/图鉴/宝箱 六路灵石 + 四路钻石。
4. **抽卡有保底（120 抽强制帝阶）**：防绝望，符合现代手游共识。
5. **战斗有深度**：双伤害类型 + 11 类主动效果 + 暴击/暴伤/命中/闪避/先攻连动 + 中毒/护盾/吸血。
6. **离线可玩 + 渐进增强**：离线结算、未配云时优雅降级。

### 仍不合理 / 缺失的环节 ⚠️
| 维度 | 现状 | 风险 |
|---|---|---|
| 社交 | 排行榜/BOSS 均为占位或本地 NPC | 单机体验，无「与人争」的核心爽点 |
| 内容深度 | 仅 M2 角色动图、无突破动画、无宗门/成就 | 中期易空虚 |
| 经济安全 | 存档明文、离线时钟可刷 | 单机可接受，但「白嫖」数字仅供参考 |
| 代码卫生 | `CULTIVATION.recalc` 已于 8/22 删除；`game_standalone.html`/`index.html.bak` 已于 8/24 标注废弃 | 已基本清理 |
| 刷新机制 | 前 10 次免费 + 第 11~20 次每次 500 灵石（已平衡） | 已解决 |

### 结论
