## 0. 一句话设计（Fun Hypothesis）

> 这部游戏好玩的核心，是「从无名小卒一路爬到天下第一」的**权力幻想**与**每日可见的进度回报**。
> 副本是线性的（推图就变强）、世界BOSS 是限时的（5 时段竞速），二者都缺一个**常驻、可见、每天都有意义**的「我到底排第几」的锚点。
> **神魔竞技场**补上这个锚点：1000 个风格各异的虚拟高手永远占着榜单，你每打赢一个就夺他的名次，每天 23:00 按你的名次发钻石——**给你一个每天回来、且永远有目标可攀的理由**。

## 1. 设计支柱（Design Pillars — 不可妥协的体验）

| # | 支柱 | 玩家能感受到什么 | 反例（绝不允许） |
|---|------|------------------|------------------|
| P1 | **排名即身份** | 我的名次数字永远挂在界面上，且每一次胜利都让这个数字变小（变好） | 排名只是装饰、赢了没反应、或数字和实际对手对不上 |
| P2 | **每日必回** | 每天 10 次免费挑战 + 23:00 准时发钻石，是一根独立于副本进度的「每日登录绳」 | 挑战次数不清零 / 钻石漏发 / 离线一天等于白打 |
| P3 | **对手像真人** | 每个虚拟对手是 6 种形象 × 6 种流派里的一个具体的人，用的武器、功法、出手节奏都不一样 | 1000 个复制粘贴的同款木桩（用户明确点名反对） |
| P4 | **可攀不可崩** | 只能靠赢往上爬；输了只扣一次挑战次数，**永不掉名次**（无 rage-quit 陷阱）；榜尾永远有「刚好打得过」的人 | 输一场掉 50 名 / 新手一进场就被榜首秒杀无处可打 |

## 2. 核心循环（Core Loop — 三层）

### Moment（一次挑战，约 30~60 秒）
选 1 / 5 个对手 → 进入**已有的回合制战斗引擎**（复用 `startBattle`，mode=`arena`）→ 胜则夺取对手名次、负则仅扣次数 → 结算弹窗显示名次变化。

### Session（一天）
10 次挑战额度，按自己当前战力尽量往上爬；界面实时显示「我的名次 / 剩余次数 / 今日结算档位」；心里记着 23:00 那笔钻石。

### Long-term（跨天）
名次随战力增长逐日累积上升；冲进前 3 有荣誉感；每日钻石稳定流入商城，形成「竞技场→钻石→抽卡/买装→更强→爬更高」的正循环。

## 3. 排名机制（Ranking）

- 榜单固定 **1000 席**（名次 1~1000），全部由**虚拟玩家**占据。
- 每个虚拟玩家按 **名次种子** 确定性生成（`seed = hash("arena#" + rank)`），**刷新页面、重开游戏，同一名次的玩家属性/名字/形象永远不变**（仿 `worldboss.js` 的 `wbHash/wbRng`，种子只依赖名次，不依赖日期——保证"这个第 327 名就是这个人"）。
- 真实玩家**初始排名 = 第 1001 名（榜外）**。只要还没打进前 1000，你就站在榜尾之外当"挑战者"。
- 一旦你击败榜上的某个对手 → 你**入榜并夺取他的名次**，他名义上落到你原来的位置（见 §4 互换语义）。

### 强度曲线（为什么这样设计）
虚拟玩家的强度以**玩家当前战力为基准**缩放，而非写死绝对数值：

```
rankFactor(rank):
  t = (1000 - rank) / 999        # rank=1000 → t=0（榜尾）；rank=1 → t=1（榜首）
  return 0.75 + (2.60 - 0.75) * t^1.15   # 榜尾≈0.75×你，榜首≈2.6×你，略凹（榜首更陡）
```

- ** rationale**：写死绝对数值会让新手被秒、老玩家觉得无聊（"我早超越这个榜了"）；以玩家为基准，则**任何进度都有可打的人、也都有打不过的人**，榜单永远"活着"。
- 榜首 2.6× 是"努力+练度+运气"才能啃下的硬骨头；榜尾 0.75× 是新手入场即胜的甜点。
- 备选被否决：绝对数值表（维护成本高、易失效）；纯随机（每次刷新对手忽强忽弱，破坏"排名即身份"）。

## 4. 夺排名互换（Rank Swap）

- **语义**：击败名次为 `N` 的对手 → 你变成第 `N` 名，对手（虚拟）落到你**原来的**名次。即两人**直接交换位置**，中间的排名不动。
- **为什么是"互换"而非"整体下移"**：最贴合用户原话"通过击败对手玩家来获取他所在的排名"，且**持久化极简**——只需存 `player.arena.rank` 一个整数，无需维护 1000 人的数组。
- **失败不掉名**：输掉挑战只消耗 1 次额度，名次不变（支柱 P4）。
- **边界**：单机版只有 1 个真实玩家，其余 999 个都是虚拟；"与真实玩家互换"在联网版才有意义，本文档不处理（存档结构已留 `rank` 单值，未来可平滑升级为真实榜）。

## 5. 挑战规则（Challenges）

- **每日额度**：`ARENA_MAX_ATTEMPTS = 10` 次/天，自然日 00:00 重置（仿 `ensureWorldBossDaily` 的 date 比对；跨天不清名次，只清次数）。
- **每次展示 5 个对手**：
  - **恰好 1 个排在你之后**（名次数字更大 = 更差），距离你 **10~50 名**。
  - **其余 4 个排在你之前**（名次数字更小 = 更好），距离你 **10~50 名**。
- **确定性 + 每开必变**：5 个对手的名次由"你的名次 + 随机抖动"生成；每次打开竞技场界面**重新抽取**（你不能背板刷同一个软柿子），但每个名次对应的虚拟玩家本身是稳定的（§3）。

### 边界处理（设计决策，需明确告知）
- **你尚在榜外（第 1001 名）时**：你之后没有人，"1 个排在你之后"无法满足。
  - **决策**：此时 5 个对手**全部排在你之前**（取榜尾 951~1000 名），界面提示"你尚在榜外，先击败榜尾对手入榜"。这是唯一无法严格满足"1 后 4 前"的情形，属合理降级。
- **你已登顶（第 1 名）时**：你之前没有人。
  - **决策**：5 个对手全部排在你之后（2~51 名），界面提示"你已登顶·神魔共主"。

## 6. 每日 23:00 结算 · 钻石档位表

- **触发**：每天 23:00（本地时）；单机离线安全——结算基于"23:00 那一刻你的名次"，而名次只在你战斗时变化，故离线期间名次=上次战斗后的名次，用当前名次结算即可，不会漏/多发。
- **发奖**：按结算时你的名次（须在 1~1000 内，榜外第 1001 名不发）发放钻石，复用 `dailyGrant('diamond', amount)`。
- **每日仅发一次**：用 `player.arena.settledDate` 跟踪"已结算日期"，防重复发放；并在"次日早上首次进入"时补结算前一天（跨天/离线不丢奖励）。

| 名次区间 | 钻石 | 备注 |
|----------|------|------|
| 500 ~ 1000 | 50 | 榜尾保底收入 |
| 200 ~ 499 | 100 | |
| 100 ~ 199 | 150 | |
| 50 ~ 99 | 200 | |
| 20 ~ 49 | 250 | |
| 10 ~ 19 | 300 | |
| 4 ~ 9 | 350 | |
| 第 3 名 | 400 | |
| 第 2 名 | 450 | |
| 第 1 名 | 500 | 神魔共主 |

> 数值来源：用户需求直接给定，无模型反推，全部为 **A 级（用户指定）**。
> 档位函数实现见 `arenaTierDiamond(rank)`，区间判断自上而下（先判 500+ 再判 200+ … 最后 rank===1）。

### 结算算法（伪代码）
```
checkArenaSettlement():
  ensureArenaDaily()
  today = arenaTodayStr()
  if player.arena.settledDate == today: return        # 今天已发过
  nowMin = arenaNowMinutes()
  if nowMin >= 23*60:
      payDay = today          # 已到 23:00，结算今天
  else:
      payDay = arenaPrevDate(today)   # 刚跨天且未到23:00，补结算昨天
      if payDay == player.arena.settledDate: return     # 昨天已发，跳过
  rank = player.arena.rank
  if rank <= 1000:
      amt = arenaTierDiamond(rank)
      if amt > 0: dailyGrant('diamond', amt); 记录 lastReward
  player.arena.settledDate = today
  saveGame()
```
- **自动触发**：竞技场界面打开时调用一次；另挂 `setInterval(checkArenaSettlement, 60000)`（仅挂一次，`window.__ARENA_TICK` 去重），实现"在线时 23:00 准时自动结算"。

## 7. 虚拟玩家生成算法（六形象 × 六流派）

每个名次的虚拟玩家由名次种子确定性生成，保证**形象、流派、名字、强度、战斗脚本**五维全部各异。

### 7.1 形象（6 种，复用游戏内主角立绘）
`ARENA_AVATARS = ['m1','m2','m3','f1','f2','f3']`（铁骨武者 / 少年侠客 / 道骨仙风 / 灵气萝莉 / 绝代佳人 / 温婉御姐）
- `avatarId = ARENA_AVATARS[ seed % 6 ]`
- 战斗中立绘直接复用 `HERO_SPRITES[avatarId]`（与主角同素材，风格天然统一）。

### 7.2 流派（6 种，决定武器/功法/战斗脚本）
```
ARENA_SCHOOLS = [
  { key:'sword',  cn:'剑修', weapon:'青锋剑' },
  { key:'blade',  cn:'刀客', weapon:'雁翎刀' },
  { key:'spear',  cn:'枪神', weapon:'寒铁枪' },
  { key:'fist',   cn:'拳师', weapon:'赤手'   },
  { key:'magic',  cn:'法修', weapon:'拂尘'   },
  { key:'poison', cn:'毒修', weapon:'毒蒺藜' },
]
schoolIdx = floor(seed / 6) % 6
```
- 每个流派一套**独有 skills + 10 回合固定出手脚本**（仿 `buildBossSkills`），保证"攻击模式不同"：

| 流派 | 战斗性格 | 代表技能（节选） | 出手脚本特征 |
|------|----------|------------------|--------------|
| 剑修 | 均衡迅捷 | 剑气斩(phys)、御剑护盾(shield)、削防(debuff) | 高频普攻+偶尔护盾，节奏稳 |
| 刀客 | 爆发吸血 | 蓄力斩(phys×12)、嗜血(lifesteal)、狂化(buff atk) | 前段蓄力，中段连续大招 |
| 枪神 | 强攻破甲 | 突刺(phys×8)、破甲(debuff def)、连刺 | 持续高压物理输出 |
| 拳师 | 刚体控制 | 崩拳(phys×9)、震退(stun)、刚体(buff def) | 慢热但带硬控，肉度高 |
| 法修 | 法术控场 | 雷法(spi×9)、冰封(stun)、灼魂(burn)、护盾 | 控制+DoT，节奏分明 |
| 毒修 | 蚀骨消耗 | 蚀骨毒(poison)、蛊惑(debuff atk)、万毒归宗(spi×7+lifesteal) | 前期下毒，后期收割 |

> 技能 effect 直接复用战斗引擎 `applySkill` 的结构（poison/debuff/stun/shield/buff/dmg/lifesteal），与世界BOSS 同源。

### 7.3 名字（确定性、各异）
`姓池 × 名池`（如 叶/萧/慕容/百里/南宫… × 惊鸿/无尘/破军/听雪…）+ 流派后缀（如「叶惊鸿·剑修」）。由名次种子驱动的 `arenaRng` 取值，保证每个名次一个稳定且不同的名字。

### 7.4 属性（以玩家为基准缩放）
```
base = 玩家当前战斗数值 (maxHp/atk/def/maxMp/spiAtk/spiDef/init/eva/spd)
f = arenaRankFactor(rank)          # §3
jit = 0.9 + rng()*0.2              # 每属性 ±10% 种子抖动，进一步拉开个体差异
stat = round(base.stat * f * jit)
```
- 这样同流派的两个虚拟玩家因种子抖动也不会完全一样；不同名次因 `f` 差异明显分层。

## 8. 战斗接入（复用现有引擎，最小化改动）

`js/arena.js` 提供 `makeArenaEnemy(rank)`（确定性生成敌人对象，含 `avatarId/skills/_script`），`battle.js` 在 4 处 `mode` 分支加 `'arena'`（仿 `'worldboss'`）：

1. `startBattle(node, mode)`：`enemy = isArena ? makeArenaEnemy(node._arenaRank) : ...`；立绘走 `HERO_SPRITES[enemy.avatarId]`、头像走 `AVATAR_MAP[enemy.avatarId]`。
2. `enemyAct(enemy)`：`(mode==='worldboss' || mode==='arena') && enemy.skills?.length` → 按 `enemy._script[_turn-1]` 精确施放（确定性、无随机）。
3. `checkEnd()`：`mode==='arena'` → 敌死 `endArenaBattle(true)` / 我死 `endArenaBattle(false)`。
4. canvas 点击：`mode==='arena'` → `openArenaResult()`。

> 注：虚拟玩家**满血满灵开局**由 `startBattle` 统一处理（`player.hp=player.maxHp` 那套），无需 arena 侧额外逻辑。

## 9. 界面（三屏，复用黑金磨砂 + bag-item/equip-btn 体系）

- **`openArenaScreen()`（主界面）**：标题「神魔竞技场」+ 规则说明 + 状态条（我的名次 / 剩余次数 / 今日结算档位）+ 5 个对手卡片（名次·名字·流派·形象缩略·估算战力·「挑战」按钮）+ 迷你榜单（前 10 + 我的位置）+ 返回主页。
- **`openArenaResult(win)`（结算弹窗）**：胜=「夺取第 N 名（原第 M 名）」+ 继续挑战/返回列表；负=「名次不变，挑战次数 -1」+ 重试/返回。
- **`arenaBoardPreview()`（迷你榜）**：前 10 名虚拟玩家名字（确定性）+ 若已入榜则高亮"你（第 N 名）"。

## 10. 边界与失败态（Edge Cases）

| 情形 | 行为 |
|------|------|
| 榜外（1001）打开竞技场 | 5 对手全在榜尾 951~1000；提示"先击败榜尾入榜" |
| 已登顶（第 1 名） | 5 对手全在 2~51；提示"你已登顶" |
| 当日次数用完（0/10） | 对手区替换为"今日次数已用完，明日 0 点重置"；挑战按钮禁用 |
| 23:00 时仍在榜外 | 不结算钻石（你不在 1~1000 内） |
| 离线跨天 | 次日首次进入补结算前一天（不丢奖励，最多 1 天延迟） |
| 读旧档（无 `arena` 字段） | `ensureArenaDaily` 自动初始化 `rank=1001, attempts=10` |
| 与真实玩家互换 | 单机版不发生（仅 1 真实玩家）；结构已预留 |
