# 逍遥仙 · 全游戏设计审查与优化清单

> 审查时间：2026-08-17 ｜ 审查范围：index.html + 13 个 js 模块 + css/style.css + online.js + 仓库结构
> 审查方式：静态通读核心文件（player/daily/codex/create/core/hub/battle/worldboss/story）+ 全仓结构化扫描 + 关键结论逐条源码复核

---

## 0. 总体结论

游戏**完成度很高**：挂机修仙闭环（属性→功法→装备→副本→世界BOSS→图鉴→每日→宝箱）已完整可玩，主页移动端风格 UI、存档、离线结算、保底/概率体系都在。但存在 **3 类严重数据完整性问题（含一个可刷钻漏洞）**、**1 块完全不可达的死代码**、以及若干历史遗留技术债与设计不一致。

建议优先级：**先堵数据漏洞 → 再清死代码/占位 → 然后做响应式与体验打磨 → 最后补"设计"层新内容**。

## 🔴 严重（必做，影响数据完整 / 经济平衡）

### S1. 存档缺口：三个关键字段不持久化，且可刷钻石
**位置**：`js/core.js` `saveGame()`（第 74–86 行）

`saveGame()` 写入了 name/sect/xp/属性/装备/背包/剧情/世界BOSS/每日/钻石等，但**漏写**了三个字段：
- `player.equipCollected`（图鉴收集集合，含已售出装备）
- `player.codexReward`（里程碑档位 `{skill:0, equip:0}`）
- `player.skillPity`（功法宝箱 120 保底计数）

**后果**：
1. `equipCollected` 每次刷新靠 `codex.js:rebuildEquipCollected()` 从 bag/equipment 重建 → **已售出的装备从图鉴永久消失**，图鉴收集进度不可信。
2. `codexReward` 每次刷新重置为 `{0,0}`，`checkCodexReward()` 在下次获得第 10/20/30… 件时再次发放 1000 钻 → **刷新即可重复领里程碑钻石（刷钻漏洞）**。
3. `skillPity` 跨会话清零 → 120 保底形同虚设，玩家体感随机性失控。

**修复**：在 `saveGame()` 的 JSON 内补三行（`equipCollected / codexReward / skillPity`）；并在 `main.js` 恢复存档处确认三者有兜底默认值（已有 `if (!player.xxx)` 保护则无需改）。

---

### S2. 排行榜 100% 占位，功能从未真正接入
**位置**：`js/hub.js:98-100` 调 `window.Online.showBoard()`；`online.js` 整文件在 `!ENV || !tcb` 时直接 `return`

- `online.js` 内部排行榜是用 `boardBtn.onclick` 实现的，**从未定义 `Online.showBoard` 这个方法**。
- 离线模式（未配腾讯云 ENV）下 `online.js` 直接 return，`window.Online` 仅是个空壳 `{ready:false}`。
- 结果：主页"排行榜"按钮永远走 `else` 分支，弹"联网功能尚未开启"。**全服排行榜实质未实现**。

**修复方向**（二选一）：
- 轻量版：把 `online.js` 里 `boardBtn.onclick` 的逻辑抽成 `Online.showBoard()`，离线时改弹"本地榜单"（复用世界BOSS本地伤害榜数据），至少让按钮有用。
- 完整版：按 PROJECT.md 计划接入腾讯云，配 `config.js` 的 `CLOUDBASE_ENV`，实现真·全服榜。

---

### S3. 江湖地图（map 模式）完全不可达，约 150+ 行死代码
**位置**：`js/battle.js` 第 23 行（`let state='map'` 初值）、565/582（地图点选）、609（`drawMap`）、711-712（render 的 map 分支）

- `state='map'` 只在 `battle.js` 初始化和地图内部返回时赋值，**没有任何 UI 入口**把状态切到 map（主页无"江湖/探索"按钮）。
- `drawMap()`、12 节点、点击发亮地点 `startBattle(n)` 的逻辑全部不可达。
- 渲染循环每帧仍跑，hub 下早退（无害），但 map 分支永不进。

**修复方向**（二选一，强烈建议"接入"而非"删除"）：
- 接入：主页加"江湖"入口 → 自由探索节点地图 → 触发野外/精英战斗，把死代码变成真正的玩法。
- 删除：若短期不做探索玩法，删除 map 相关代码减体积、降维护成本。

## 🟠 中等（建议做，体验 / 一致性 / 数值漂移）

### M1. 双 1 秒定时器并存
**位置**：`js/hub.js:197`（`setInterval` 每秒 `syncRealmDOM` 境界/进度条）+ `js/daily.js:191`（`setInterval` 每秒 `dailyTickSeconds`）

两个独立 1s 定时器同时跑。**建议合并为单一主循环 tick**，或把 idle 同步并入每日 tick，减少定时器数量（也便于将来加"整点事件"等）。

### M2. 套装/特效被双重计算，存在数值漂移风险
**位置**：`js/player.js` `recalcStats()`（195–216 行，算面板常驻 crit/set）+ `js/battle.js` `computeEquipMods()`（100–143 行，算战斗运行时全部 effect）

- `recalcStats` 只把 `effect.type==='crit'/'critdmg'` 和套装 two/four 的 `critRate/critDmg` 计入面板；
- `computeEquipMods` 计算全部 effect（吸血/反弹/穿透/增伤/护盾/灼烧/低血暴击…）供实战。
- 两处对 crit / 套装的映射各自写一遍，未来改一处易漏 → **面板显示与实战数值不一致**。

**建议**：以 `computeEquipMods` 为唯一真源，面板 crit 值复用其输出，避免双份维护。

### M3. `index.html` 残留旧 demo 说明文字（误导新玩家）
**位置**：`index.html` 第 6 行 `<title>…Demo</title>`、12 行 `<h1>…Demo</h1>`、13 行"节点地图探索 + 一场回合制战斗（纯 HTML5 Canvas，零依赖）"、26–30 行"地图上点击发亮（蓝色）的地点进入战斗"等提示。

这些全是**旧 demo 时期文案**，与现在完整游戏（hub/副本/世界BOSS/图鉴/每日/宝箱）严重不符。**建议更新**为当前功能描述与操作引导。

### M4. 仓库双 HTML 重叠，体积与混淆风险
**位置**：根目录 `index.html`（线上）、`game_standalone.html`（旧单文件快照）、`index.html.bak`（历史备份）。

> **2026-08-24 状态更新**：二者已于 2026-08-24 标注「废弃」——内容替换为跳转提示页（`<meta http-equiv="refresh">` 指向 `index.html`），不再含旧游戏逻辑，GitHub Pages 直接访问时也不会误导。残留体积问题可通过后续 `.gitignore` 或 `git rm` 进一步清理（当前用 deploy_api.py 仅支持推送/覆盖，不支持删除）。

### M5. 创建角色"门派"概念与 online.js 不一致
**位置**：`js/create.js:96` `player.sect = createData.avatar.desc`（门派=形象描述）；`online.js:61` 门派是固定列表（少林/武当/峨眉/华山/丐帮/明教）。

两处"门派"语义不同、数据来源不同。**建议**：明确门派是"玩法标签"还是"身份"——要么创建时让用户选门派（影响初始功法/属性），要么把 sect 仅作形象标签、排行榜不用门派维度。

## 📐 数值与经济系统专项

- **挂机经济**：在线 2 xp/s、离线 1 xp/s（封顶 12h）、`xpBonus = (悟性+天命)×0.2%` —— 节奏合理，离线封顶防止爆肝。✅
- **货币双轨**：灵石（gold，装备/商店）+ 钻石（diamond，商城/签到/图鉴里程碑）—— 结构清晰。⚠️ 但 S1 的 codexReward 刷钻漏洞会破坏钻石稀缺性，需优先堵。
- **宝箱保底**：功法宝箱 120 抽保底（skillPity），但 S1 导致保底跨会话清零，需补持久化。
- **图鉴里程碑**：每满 10 件发 1000 钻，设计合理，但依赖 `codexReward` 持久化才不会被刷。
- **装备数值**：`RARITY` 系数（1.0/1.5/2.2/3.2/4.6）+ 境界缩放，梯度平滑。⚠️ M2 的双份计算若某处漏改会出现"面板与实战不符"的客诉。
